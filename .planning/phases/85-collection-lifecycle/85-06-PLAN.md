<objective>
Deliver LIFE-05's visibility model: the owner-only "Show previously owned" toggle on the live Collection tab (`CollectionTabContent`, not the dead `CollectionView` island), fed by an owner-only data split in the tab page, plus the matching visitor exclusion on the Notes tab.

Purpose: previously-owned watches are hidden by default and never cross the server→client boundary for visitors (D-13). The muted card, badge and ⋯ menu are 85-08; this plan owns data flow, toggle and empty-state logic.

Output: updated tab page and CollectionTabContent with component tests.

Discretion choices:
- The toggle is a sibling `<button>` styled with FilterChips' own active/inactive classes (UI-SPEC), not a new Switch primitive and not a change to FilterChips' props.
- Role-tag chip options stay derived from owned watches only, so turning the toggle off can never leave the user on a chip that no longer exists; the active chip and search still filter previously-owned cards when the toggle is on.
- Toggle state is plain `useState(false)`. It is never persisted (D-15). The Next 16 Router Cache can restore a stale client instance on soft back-navigation (project memory); 85-11's walk checks whether the toggle is off after leaving and returning to the tab and records the result.
</objective>
