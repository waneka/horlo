<objective>
Implement the server-side lifecycle contract: a dedicated owner-only `markWatchPreviouslyOwned` Server Action (the disposal dialog's commit), the D-04 undo and D-07 guard rules inside `editWatch` / `addWatch`, and the D-09 promotion signal returned by `editWatch` and `moveWishlistToCollection`.

Purpose: every UI plan after this (85-06 dialog, 85-07 celebration, 85-08 edit form) consumes these signatures. The server is the trust boundary for reason-required, no-future-date, ownership and transition detection.

Discretion choices made here:
- Dedicated `markWatchPreviouslyOwned` action instead of routing the dialog through `editWatch` — keeps the "reason required + only from owned" contract explicit and lets `editWatch` hard-reject transitions into previously_owned (D-07).
- The disposal action uses `updateTag('profile:<username>')` (read-your-own-writes, the Phase 84 `logBackfillWear` precedent) instead of `revalidateTag(..., 'max')` for the profile tag, because D-08 requires the card to leave the grid while the user stays on the tab. All other D-08 invalidations match the existing watch-mutation fan-out.
- `moveWishlistToCollection` keeps rejecting grail (T-70-03; the add-flow DupeBanner only offers it for wishlist dupes). Grail → owned promotion happens through `editWatch`, which covers D-09's grail case.
- `isoCalendarDate` / `isPlausibleClientToday` move out of the `'use server'` wearEvents file into a plain module, because a `'use server'` file may only export async functions and both actions now need them.

Output: new shared helper module, `WatchEditResult` type, extended actions, and a new lifecycle test file.
