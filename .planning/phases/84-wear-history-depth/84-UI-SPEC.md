## Spacing Scale

Declared values (must be multiples of 4), matching the project-wide convention already visible in `WornTabContent`/`WornCalendar`/`WornTimeline`:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps, badge/pill inner padding (`px-1`, `gap-1`) |
| sm | 8px | Row internal gaps (`gap-2`), compact stacks (`gap-2`, `p-2`) |
| md | 16px | Default card padding (`p-4`), section gaps (`gap-4`), form field stacks (`gap-4`) |
| lg | 24px | Section-to-section spacing above/below the leaderboard block |
| xl | 32px | Not used on this phase's surfaces |
| 2xl | 48px | Not used on this phase's surfaces |
| 3xl | 64px | Not used on this phase's surfaces |

Exceptions:
- Touch targets: every tappable row (leaderboard row, window-control segment, timeline/calendar wear row) must resolve to **44×44px minimum hit area** on mobile even where the visible content is smaller (e.g. a 40px thumbnail row still needs `py-2`+ vertical padding so the full `<li>`/`<Link>` hit area clears 44px). This mirrors the existing `size-10`/`size-12` thumbnail + row padding pattern in `WornTimeline`/`WornCalendar`.
- Leaderboard row thumbnail stays `size-10` (40px) to match `WornTimeline`'s existing thumbnail size — do not introduce a new thumbnail scale.

## Typography

Matches the project's established 2-weight system (no `font-medium`/500 or `font-bold`/700 introduced in new code; shadcn base components like `Button` already use `font-medium` internally and are left as-is):

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body / row text | 14px (`text-sm`) | 400 regular (`font-normal`) | 1.5 |
| Label / emphasis (watch name, section heading) | 14px (`text-sm`) | 600 semibold (`font-semibold`) | 1.5 |
| Micro / meta (wear count, date meta, "0 wears") | 12px (`text-xs`) | 400 regular (`font-normal`), `text-muted-foreground` | 1.5 |
| Section heading ("Wear leaderboard") | 16px (`text-base`) | 600 semibold (`font-semibold`) | 1.2 |

Rules:
- Rank number, watch Brand+Model, and the window-control active label use `font-semibold`. Wear-count numerals and helper copy use `font-normal`.
- No `font-medium` or `font-bold` in any newly written JSX for this phase.

## Color

Matches the existing OKLCH token set in `src/app/globals.css` (warm neutral base + amber/gold accent) — no new tokens introduced:

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `bg-background` (`oklch(0.985 0.003 75)` light / `oklch(0.14 0.005 75)` dark) | Page background, Worn tab wrapper |
| Secondary (30%) | `bg-card` / `bg-muted` (`oklch(1 0 0)` / `oklch(0.95 0.005 75)` light) | Leaderboard card container, row hover background, empty-state box |
| Accent (10%) | `bg-accent` / `text-accent-foreground` (`oklch(0.76 0.12 75)` light / `oklch(0.78 0.13 75)` dark) | **Reserved for: (1) the active segment of the window-control, (2) the proportional wear-count bar fill, (3) the "today" ring on calendar day cells (pre-existing, unchanged).** Never used for static text, borders, or non-interactive/non-selected decoration. |
| Destructive | `text-destructive` / `bg-destructive/10` | Backfill form's duplicate-date error message and any server-error banner (matches `LogTodaysWearButton`'s existing `role="alert" text-destructive` pattern) |

Accent reserved for: the window-control's active pill (1 mo/3 mo/6 mo/12 mo/All), and the leaderboard bar fill. Do NOT apply `bg-accent` to the "Log a wear" button (that stays `variant="default"` per existing `LogTodaysWearButton`, i.e. `bg-primary`) — accent is the active/selected token, primary is the button-CTA token (per `project_accent_is_active_token`).

Every `bg-accent` usage that also needs a light/dark distinction beyond the existing token swap must NOT add a raw-palette override; if an outline-style button variant is introduced anywhere in this phase, pair any `bg-*` override with an explicit `dark:` variant (per `feedback_button_outline_dark_override`).

## Interaction Contract

### Backfill / unified log form (WEAR-02)
- Trigger: existing "Log a wear" button/dialog (`LogTodaysWearButton`), unchanged trigger location (Worn tab header row, owner-only).
- Dialog layout order: Watch select → Date input → Note (progressive-disclosure "+ Add a note" toggle, reuse `ComposeStep` pattern) → Visibility (`VisibilitySegmentedControl`) → error slot → Cancel/Log wear footer.
- Date input: native `<input type="date">` (no calendar library — matches `WatchForm.tsx:805` precedent), `max={todayLocalISO()}`, no `min`. Changing the date must re-run the owned-watch-worn-that-day preflight and disable already-logged watches in the select list (mirrors `WatchPickerDialog`'s `wornTodayIds` disabled-row pattern, extended to be date-aware).
- Mobile presentation: keep as a `Dialog` (not a `Sheet`) — the existing `LogTodaysWearButton` and `WatchPickerDialog` both use `Dialog` on this surface at all breakpoints; introducing a `Sheet` here would be an inconsistent pattern-fork. `DialogContent` already center-modals responsively; no new mobile-only sheet needed for this phase.

### Window-control segmented tabs (WEAR-03)
- Use `src/components/ui/tabs.tsx` (shadcn `Tabs`/`TabsList`/`TabsTrigger`) OR clone the `ViewTogglePill` visual shape with 5 segments instead of 2 — planner's choice, but whichever is used MUST implement the WAI-ARIA roving-tabindex + arrow-key pattern already established for the radiogroup/tab convention in this project (Phase 68 lesson), not a plain row of independent buttons with only click handlers.
- Active segment: `bg-accent text-accent-foreground` (matches `ViewTogglePill`'s existing active-state classes exactly — do not use `bg-primary`).
- Default selected: **3 mo** (D-09).
- Placement: directly above the existing `ViewTogglePill` (Timeline/Calendar) row, inside its own `rounded-xl border bg-card p-4` container consistent with `WornCalendar`'s card shell. Always visible, not collapsible (D-08).

### Leaderboard rows (WEAR-04)
- Row shape (left to right): rank number (`text-sm font-semibold`, fixed-width ~`w-5`), thumbnail (`size-10` rounded, `object-cover`, `WatchIcon` fallback exactly like `WornTimeline`), Brand+Model (`text-sm font-semibold`, truncate), wear count (`text-xs text-muted-foreground`, right-aligned or trailing), thin proportional bar (`h-1.5 rounded-full bg-muted` track + `bg-accent` fill sized to `count / topCount * 100%`, paired `dark:` variant unnecessary since `bg-accent`/`bg-muted` already resolve per-theme via CSS variables).
- Zero-wear rows: same shape, bar renders at 0 width (or a hairline), count reads "0 wears", sorted to the bottom per D-13.
- Row is a `Link` to `/w/[id]` (D-12) — wrap the whole row (not just the thumbnail or name) so the full row is the 44px+ tap target, matching `MostWornThisMonthCard`'s whole-card-as-Link pattern.
- Default visible: top 5 rows, then a "Show all" text-button expander (`variant="link"` or a plain `button` styled like the existing `text-sm text-muted-foreground hover:text-foreground` micro-link pattern used for month-nav chevrons in `WornCalendar`).

### Timeline/Calendar row linking (WEAR-01, D-15)
- `WornTimeline`: wrap each day-event `<li>`'s inner content in a `Link href={/wear/${e.id}}` (or wrap the `<li>` itself) — preserve the existing `flex items-center gap-3 rounded-lg border bg-card p-2` visual shell exactly; only add the link behavior + a focus-visible ring (`focus-visible:ring-2 focus-visible:ring-ring`, matching `MostWornThisMonthCard`'s existing focus pattern) and a hover affordance (`hover:bg-muted/40`, matching the row-hover convention already used in `WatchPickerDialog`).
- `WornCalendar`: wrap each selected-day-panel `<li>` (the below-grid list, not the grid day-cells) the same way. Day-cell click-to-select-a-day behavior is UNCHANGED — only the resulting panel rows below the grid become links.
- Add a subtle chevron-right (`ChevronRight` from lucide, `size-4 text-muted-foreground/40`) at the trailing edge of each now-clickable row so the affordance reads as navigable, not just decorative — consistent with using an existing icon already imported in `WornCalendar` (`ChevronRight` is already imported there for month nav; reuse the same icon, new usage).

### Dates / hydration
- Any new date formatting in client components MUST pin `timeZone: 'UTC'` + locale `'en-US'` exactly like `WornTimeline.formatDateHeading` and `WornCalendar.monthLabel` (React #418 guard).
- Rolling-window math (D-13: 30/90/182/365/all days) computed client-side from `todayLocalISO()` — never server-computed "today" (260622-exo invariant already documented in `src/lib/wear.ts`).
