<objective>
WEAR-03 + WEAR-04 (component): build `WearLeaderboard`, a self-contained client section. It has the "Wear leaderboard" heading, a 5-segment rolling-window tablist (default 3 mo), and ranked owned-watch rows with thumbnail, count and a proportional accent bar. It shows the top 5 with a Show all expander, links each row to `/w/[id]`, and shows the "No wears in this window." note when every count is zero.

Purpose: this makes neglected watches visible and shows which watches the collector actually reaches for in a chosen window.

Discretion choice (documented): the window control clones the `ViewTogglePill` visual shape and ports `ConfirmStep.tsx`'s roving-tabindex `handleKeyDown`, instead of using `ui/tabs.tsx`. Reasons:
- UI-SPEC requires `bg-accent text-accent-foreground` for the active segment. `TabsTrigger` ships `data-active:bg-background` plus `font-medium` styling that would need heavy overrides.
- A hand-ported handler is deterministic under jsdom, so keyboard behavior is unit-tested rather than assumed (RESEARCH Assumption A1).
UI-SPEC explicitly allows either option provided roving tabindex is implemented.

Output: WearLeaderboard.tsx plus its RTL test. It is not mounted yet; 84-06 mounts it.
</objective>
